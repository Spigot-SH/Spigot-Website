Spigot Design System
Foundations

Introduction

The design system for Spigot — APIs and tools you can call without a subscription, metered per request. Every token here is defined in UI.md, and every contrast ratio was computed rather than estimated.

Precedence

Layer 0 repo hard rules always win. This system is Layer 1 — project truth. Aesthetic skills are advisory against it, never above it.

Layer What Authority
0 Repo hard rules — Tailwind @theme, SSR, routing Always wins
1 This system Project truth
2 Aesthetic skills Advisory
3 Performance & code-volume skills Advisory
4 Audit gate Blocking, runs last

The rules that shape everything

Rule Consequence
Borders define boxes, not fill panel is 1.16:1 against pure black. A surface cannot separate itself by background alone
One accent, under 5% of surface Primary action, focus, current nav item, links. Nothing else
Selection is neutral, focus is accent Both were accent once — a keyboard user could not tell them apart
Colour is never the only signal Every state carries a dot, icon or label alongside the hue
Machine values are mono, tabular Proportional digits make a column of amounts unscannable
Anything that appears reserves its space Otherwise it shifts layout at the moment the user is looking

Foundations

Adding a page

What has to be true before a page exists, what it must contain, and what to run afterwards. The system documents more than the codebase ships, which is allowed, but only when each page says so.

Every page declares a status

The chip beside the group name. It is not decoration: it is the difference between a page you can build against and a page that is an argument for what to build.

Status Means Test
Shipped A primitive exists and the page describes it components/common/<Name>.tsx
Spec The page runs ahead of the code. It is a contract, not a description No primitive. Often a raw element inlined in a view
Foundation Tokens, rules or voice. There is no primitive to have Backed by @theme or by prose, not by a file
A SPEC PAGE NAMES WHAT IS MISSING

Not in a footnote. A visible note saying which file does not exist and which views are hand-rolling it instead, as the Select page does. A page that quietly describes something unbuilt is the one failure mode this system cannot survive: it makes every other page suspect.

What a page must contain

  • An eyebrow naming the group, and a title that is the name the code uses. If the page and the file disagree on the name, one of them is wrong.
  • A lede of one or two sentences saying what the thing is and the single decision behind it. Not a feature list.
  • At least one demo, rendered, with the real tokens. A screenshot or a description is not a demo.
  • Guidance, in the buckets below, but only the buckets that have something true to say.
DO NOT MIRROR ANOTHER SYSTEM'S PAGE

Geist's Button page has eleven sections because Vercel needed eleven, not because eleven is correct. A page gets the sections it has been asked for. Speculative structure looks like thoroughness and behaves like debt.

The four guidance buckets

Always in this order, and never renamed. Omit any bucket with nothing true in it. Twenty of the sixty-seven pages in the system that inspired this have no guidance at all, and that is a signal rather than an omission.

Bucket Answers The tell
When to use Which component, not how Always names the sibling to switch to instead
Behaviour Runtime, state, timing Defaults, and what not to do automatically
Content The words in the UI Casing, sentence shape, forbidden strings
Accessibility Roles, keys, focus Required aria, keyboard map, where focus returns
WHEN TO USE IS THE ONE THAT EARNS ITS PLACE

A bucket that only describes the component is worth nothing. The first bullet should send the reader somewhere else when this is the wrong choice. That is what turns a list of components into a decision tree.

Wiring a new route

Four edits, in this order. The status, icon and title live in one place so the sidebar, the status chip and the generated Markdown cannot drift apart.

1. app.js add to ROUTES: { id, title, group, icon, status } 2. index.html <section class="route" id="<id>"> … </section> 3. npm run designsystem:llm regenerates <id>-llm.txt and llm.txt 4. npm run verify && scripts/security-review.sh The nav, the pager, the search palette and the copy button all read ROUTES. None of them need touching.

The Markdown mirror is generated

Every page is also a .txt file, and the whole system is one llm.txt. They are build output.

  • Run npm run designsystem:llm after any content change. Forgetting it leaves the Markdown describing the previous version of the page, which is worse than having no Markdown.
  • Never edit a -llm.txt by hand. The next run overwrites it. Change the page.
  • The generator reads index.html for content and app.js for order and status, so the sidebar and the mirror always agree.

When not to add a page

  • There is no surface for it. A page for a component this product will never render is debt with a table of contents.
  • It duplicates a page that exists. Extend the page instead; two half-pages on one topic are worse than one.
  • It documents a variant rather than a component. Variants are sections.
  • You are matching another design system's page count.
IF SOMETHING LOOKS MISSING, SAY SO AND STOP

Naming a gap costs a sentence. Filling it uninvited costs a review and often a revert. The queue of pages that are wanted but not yet earned lives in DESIGNSYSTEM-PLAN.md.

Depth

In-page surfaces get no shadow — depth is a value shift plus a hairline. Overlays get one shadow token and a frosted scrim.

Modal surface

shadow-overlay + blurred scrim

--shadow-overlay: 0 16px 48px -12px rgb(0 0 0 / 0.45) --glass-blur: 10px No sm/md/lg scale. The enforcement grep fails any shadow-{sm,md,lg,xl,2xl}.

Frosted glass

DELIBERATELY WEAK

Every contrast ratio assumes an opaque backdrop. A translucent surface inherits what is behind it, so glass opacity stays at 0.88 or above and blur at 10px. Allowed on the header, scrims, dropdowns and toasts — never on cards, tables, rows or inputs. --color-glass must stay legible with blur disabled entirely.

Foundations

Motion

Three durations, two curves. Fast enough to read as response, never as a transition you wait through.

Durations

Token Value Applies to
--dur-1 90ms Press. Buttons and options scale to 0.97
--dur-2 140ms Hover, colour, focus ring, row highlight
--dur-3 200ms Overlays, disclosure, theme swap

Curves

Enter and exit are not the same curve. A decelerating exit feels reluctant — things leaving should accelerate away.

Token Curve Direction
--ease cubic-bezier(0.16, 1, 0.3, 1) Enter — settles
--ease-in cubic-bezier(0.4, 0, 1, 1) Exit — accelerates

Try them

Toggle
Only opacity and transform animate — both composite on the GPU and never trigger layout. Anything that appears reserves its space: the copy check and the option tick render at opacity:0 rather than being absent.
REDUCED MOTION IS HONOURED

prefers-reduced-motion: reduce drops every duration to 0.01ms and removes press transforms. The state change still happens — it just arrives instantly. Nothing disappears.

When to use

  • A fixed set of machine values about one subject: a settlement receipt, an endpoint's price and method.
  • A row that needs a control on the right is a table row, not a spec row. Prose is body copy.

Behaviour

  • Label left, value right, value in mono tabular. Below --bp-sm the value drops under the label rather than wrapping mid-number.

Content

  • An unknown value is —. Never N/A, never null, never blank, because a blank cell reads as a rendering bug.

Accessibility

  • It is a definition list. <dl>/<dt>/<dd>, so the pairs are announced as pairs and not as a run of unrelated text.

Middle truncation

A transaction hash and a wallet address carry information at both ends: the head identifies, the tail disambiguates. Cutting the tail off makes two different values look identical.

TRANSACTION
QK7X2MJ4NR8VP…9FA3D1
PUBLISHER WALLET
ALGO7YHT2KQ…M4XQ9Z
One ellipsis glyph (…), never three periods. Copying yields the full value, never the shortened form. The full value is the element's accessible name.
NEVER ON PROSE

Middle truncation is for values, not sentences. Cutting the middle out of a sentence destroys its meaning. A sentence that is too long is truncated at the end, or not at all.

When to use

  • Above a block, to name it. As structural numbering only where the number encodes real sequence. Wizard steps do; a feature list does not.

Behaviour

  • Mono caps in muted. Never the action role: a button label is normal case, because a label names and an action commits.

Content

  • One or two words. No sentences, no punctuation.

Accessibility

  • The uppercase is styling, not content. Write it normal case in the markup and let text-transform do the work, or a screen reader spells it out letter by letter.
Patterns

Imagery

Dot-matrix primary, SVG line-art secondary. Dot size encodes the value, so the treatment carries data rather than only decorating.

Dot-matrix

CALL VOLUME — DOT SIZE ENCODES VALUE
Generated in CSS or canvas, never a raster asset. A PNG would not respond to the theme switch — the same class of bug as the 35 fixed-hex palette values this system replaces.

Line-art

Hairline SVG with currentColor stroke, no fills. Subjects are structural: request/response flow, settlement path, gateway topology. Touch, not texture.

When to use

  • Dot-matrix for a quantity that has a shape. Line-art where a photograph would be a lie. Never stock photography.

Behaviour

  • Deterministic. Every figure is derived from a hash of its input, so the same input always draws the same picture. Math.random() would break server rendering anyway.

Accessibility

  • Decorative, so aria-hidden="true". If a figure carries the only copy of a number, that number also appears as text.

Placeholders

Stand-ins for decisions not yet made — the brand name, the fee, the domain, the logo. All generated in CSS, all theme-responsive, all deliberately conspicuous. A placeholder that looks finished is worse than no placeholder.

THEY CANNOT SHIP SILENTLY

The bracketed-caps form is greppable and appears in no real code. One command finds every unresolved value: 

grep -rnE "\\[[A-Z_]{3,}\\]" frontend/src .agents

That grep becomes a release gate. A placeholder that reaches production is a naming failure, not a content one — this makes it a build failure instead.

When to use

  • While the real asset does not exist yet. A placeholder is a promise that something is coming, not a design.

Behaviour

  • Reserves the exact space the real thing will take, so nothing moves when it lands.

Content

  • A placeholder that ships is a bug. Every one of them is tracked.

Accessibility

  • Never alt="" on a placeholder standing in for meaningful content. That hides the gap from exactly the users who most need it named.

Foundations

Grid

A 12-column grid on a 4px base. Layouts are composed from column spans, not from arbitrary widths — that is what keeps two pages built months apart looking related.

Columns

12 columns, 24px gutter, 4px base unit. 12 divides by 2, 3, 4 and 6 — halves, thirds, quarters and sixths all land on the grid. 10 or 16 columns do not.

Common spans

4-4-4 three metric cards 8-4 content with a side rail 12 tables, wizard steps, anything dense Below --bp-md every span collapses to 12.

Container widths

Context Max width Why
Reading copy 68ch Measure, not pixels — it holds across type sizes
Docs / forms 940px Comfortable for a single column of dense content

Dashboard 1400px Tables earn the extra width
CONTENT STOPS GROWING BEFORE THE VIEWPORT DOES

A line of text 2000px wide is unreadable regardless of font size. Past the maximum, the gutters take the space — which is why the shell has vertical rules rather than a stretched layout.

Foundations

Accessibility

Not a checklist bolted on at the end. Every rule below already constrains a token or a component elsewhere in this system — this page is where they are stated together.

Contrast

Every foreground/surface pair was computed, not estimated. All 42 clear AA for body text.

Target Ratio Applies to
AA body 4.5:1 All text, including state colours on their surface
AA non-text 3:1 Categorical dots, focus rings, meaningful boundaries
Decorative none Hairline borders — which is why they carry no meaning

Focus

2px accent ring at 2px offset, on every interactive element. Focus is accent; selection is neutral — they were both accent once and a keyboard user could not tell them apart.

Colour is never the only signal

Roughly 1 in 12 people cannot rely on hue. Every state carries a dot, an icon or a text label alongside the colour: StatusBadge pairs a dot with mono caps, Input errors carry an icon, banners carry both.

Motion

prefers-reduced-motion: reduce drops every duration to 0.01ms and removes press transforms. The state change still happens — it arrives instantly. Never remove the state change itself. Skeleton is the one sanctioned loop, and it falls back to a flat opacity.

Targets and semantics

Rule Why
44x44px minimum touch target Below this, taps miss on a phone
Native elements first Select uses a real <select> for keyboard, screen-reader and mobile-picker behaviour
Disabled means disabled Styling something to look disabled still lets it be focused and clicked
Tooltips open on focus too :has(:focus-visible), not hover alone — touch has no hover
Icon-only controls carry aria-label The hamburger and theme toggle both do
Foundations

Content

The words are part of the system. A component with improvised copy is as inconsistent as one with improvised colour.

The site does not name the payment rail

These appear nowhere in user-facing copy, metadata, titles or alt text:

Arc · blockchain · crypto · stablecoin · USDC · wallet · on-chain · web3 · micropayment · gas

This is positioning, not squeamishness. The audience is a developer who wants an API call to work. The settlement mechanism is an implementation detail that happens to be excellent — leading with it filters out everyone who is not already crypto-native, which is most of the market.

Instead of Say
Settles in USDC on Arc Metered per request
No wallet needed No signup, no subscription
Stream micropayments Pay for exactly what you use
On-chain settlement Every call is metered and receipted

Code identifiers are out of scope — usdcAssetId is not copy. The ban is on what a reader sees.

Voice

Rule Example
Lead with the mechanism, not the adjective "Settles in ~4 seconds" beats "lightning fast"
Numbers over claims If you cannot source a number, cut the sentence
One idea per paragraph The reader is scanning, not reading
Second person for publishers "Sell your API by the call"

Never

Invented customers, logos, testimonials or usage numbers. Performance claims without a measurement. Any implication of production readiness while the badge says Testnet. Structured data for things not on the page.

EMPTY STATES ARE COPY, NOT CHROME

"No APIs published yet" and "No calls in this period" are different situations and get different words and different actions. "No data" is not an empty state.

States

Focus ring uses accent, never border. border is 1.35:1 and would be invisible.

When to use

  • Anything that mutates state: publish, settle, unpublish, top up. Navigation that changes the URL is a link. A button that only navigates loses middle-click and open-in-new-tab.
  • One primary per view. It is the accent, the accent is capped at 5% of surface, and a second primary halves the meaning of the first.
  • danger is for irreversible or billable actions. Unpublishing an API is danger; cancelling a form is secondary.

Behaviour

  • Disable only when the action is genuinely impossible (unverified domain, zero balance), and name the reason next to it. A dimmed button with no reason reads as broken.
  • A button that fires a request stays focusable while it runs, and carries its own loading state. Six views currently place a hand-rolled spinner beside a button instead; that is the button's job.

Content

  • Title Case, Verb + Noun, naming what happens: Publish API, Top Up Credit. Never Submit, OK or Confirm.
  • The button verb and its toast verb are the same word. Publish API is confirmed by API published, not by Done.
  • Cancel stays literally Cancel.

Accessibility

  • Focus is the accent ring, never the border: border is 1.35:1 and would be invisible.
  • An icon-only button carries an aria-label naming the action and its target: Copy publisher ID, not Copy.
  • Never put aria-label on a button that already has visible text. It replaces the label rather than adding to it.

Foundations

Layers & breakpoints

Two scales that were previously ad hoc. Every z-index in the system now comes from a named token, and every breakpoint has a name rather than being a number picked at the point of use.

Layer scale

Seven steps, ten apart. The gaps exist so something can be slipped between two layers without renumbering the rest.

Token Value What sits here
--z-base 0 Page content
--z-sticky 10 Sticky table headers, shell rules
--z-header 20 App header
--z-dropdown 30 Select menus, tooltips, popovers
--z-overlay 40 Scrims and drawers
--z-modal 50 Modals, command palette
--z-toast 60 Toasts — always on top, they report on the thing you just did
NO BARE Z-INDEX

A literal z-index: 9999 is a bug report waiting to happen. If something needs to sit between two layers, add a token — do not invent a number at the call site.

Breakpoints

Media queries cannot read custom properties, so these are documented rather than enforced. The value of naming them is that everyone reaches for the same four numbers.

Token Width Behaviour change
--bp-sm 640px Spec rows stack label-above-value
--bp-md 900px Sidebar collapses; tables scroll horizontally
--bp-lg 1180px Multi-column layouts become available
--bp-xl 1320px Shell reaches max width and gutters appear

Copy affordance

Three surfaces copy to the clipboard: a code sample, the domain verification token, and this site's own Copy page as Markdown. One control, one confirmation, everywhere.

Idle: copy glyph, muted Copied: check glyph, success, for 1.5s The glyph changes shape as well as colour, so the confirmation still reads with hue removed.
CONFIRMATION IS A SHAPE, NOT A COLOUR

It reverts after 1.5 seconds: long enough to notice, short enough that the control is ready again before the user is. Nothing about the copy is announced twice: the button label stays put and only the glyph moves.

When to use

  • A response body, a request, or a shell command the reader will copy. A single token inside a sentence is <code>, not a block.

Behaviour

  • Code is white-space: pre and never reflows. A narrow viewport scrolls it; it does not wrap it.
  • A shell prompt is drawn by the block and is not part of what gets copied.

Content

  • Samples stay runnable. Real values, or placeholders that are obviously placeholders. Never invented syntax that would fail if pasted.

Accessibility

  • The copy control is a real button with a label, and its confirmation changes shape as well as colour.

Motion (§4.4) bans looping animation everywhere else. Skeleton is the deliberate exception: a loading indicator that stops moving reads as frozen. Under prefers-reduced-motion the pulse is removed and a flat 0.7 opacity is used instead — still visibly a placeholder, no movement.

Data filling a layout whose shape is known Skeleton Shipped Reserve the shape and nothing shifts when it lands

Toast & Banner

Two ways to report an outcome. A toast is transient and reports something that just happened; a banner is persistent and reports a condition that is still true.

Toast — transient

Fires bottom-right. Auto-dismisses after 4.5s.
Bottom-right stack, newest at the bottom. Enter slides 10px and fades over --dur-3. Auto-dismiss 4.5s, or dismissed manually. z-index: var(--z-toast) — above everything, because a toast reports on the action you just took.

Banner — persistent

Low balance Add credit to keep calls flowing.
Payment failed Not enough credit for this tier.
Provisioning Your account is being set up.
Inline, above the content it concerns. Solid fill in the state colour, fully rounded, with text and dot in --bg so they invert per theme. The one place rounded-full is used besides avatars.
CHOOSING BETWEEN THEM

If the user can do nothing about it and it is already over, toast. If it describes a state they must resolve — low balance, unverified domain, failed provisioning — banner. A toast for a persistent condition disappears before it can be acted on.

Behaviour

  • Fires bottom-right, auto-dismisses at 4.5s, and sits at --z-toast above everything else.
  • One toast per flow: the terminal step, not one per stage. A publish that emits four toasts has told the user nothing four times.

Content

  • One sentence, sentence case, no trailing full stop.
  • Completion reads {Noun} {past participle}: API published, Payment settled. Never successfully.
  • The toast verb matches the button verb that caused it.

Accessibility

  • The toast region is aria-live="polite".
  • No primary navigation inside a toast. It is gone before a keyboard user reaches it.

Avatar

An uploaded image when there is one; a 5×5 dot grid seeded on the name and the date the entity was created when there is not. One of only two places in this system where rounded-full is permitted.

Sizes & stack

+4
28px default, 40px large. 5x5 dot grid mirrored down the centre. Seed = FNV-1a of `name|createdAt`. The creation date is stored and passed in, never read from the clock: two publishers called Acme then differ, and each one keeps the same avatar forever. <Avatar name="Acme" src={logoUrl} seed={createdAt} /> One hue per avatar from the CATEGORICAL ramp, with a second slice of the hash varying the weight. Categorical and not semantic, because an identity is a category and never a health state.

When to use

  • To identify a person, publisher or team in a row or a header.

Behaviour

  • Image first. The grid is the fallback, not the default, and a broken or slow URL falls back to it rather than to a broken-image glyph, so a dead link degrades to something deliberate instead of something that looks like a bug.
  • Pattern first, hue second. Read the hue alone and two people can look alike; read the pattern and they never do. That ordering is what keeps it safe at 28px, where the grid is legible and the tint is barely a suggestion.
  • The seed is stored, never computed at render. Reading the clock here would draw a different avatar on the server than in the browser, which React reports as a hydration mismatch.

Content

  • Pass the full name, not initials and not a truncation. It is both the seed and the accessible name, and shortening it collides more often.

Accessibility

  • The accessible name is the entity's name, not the word avatar.
